# 执行编排手册（阶段 6 用：多 agent 并发实施 + 验收评审）

规划落定后的 apply 阶段 SOP。

**总纲**：编排者对**终态**负责（集成与裁决的唯一越域者），agent 对**本单（白名单内的孙任务）**负责——凡报必验、凡修必回归；子 agent 完成情况必须协议化核查（§四 四查），未完成/遗漏者归因后修计划再重派；执行期发现的计划缺口必须回写。**载体**：四类纪律固化在 `ORCHESTRATION.md`（§〇），不活在会话记忆里（R27）。R6–R28 为执行期反模式详版（编号是跨文档引用锚，不重排语义只重组归属）。

**泛化约定**：规则按**通用条件→动作**表述，适用于任意语言/栈的计划-实施工作；具体项目细节（包名/命令/路径）仅作"实证"背书，不构成规则边界；命令给出跨栈等价映射（Go/Rust/TS/Python 各有对应形态）；栈特异性条款标注适用面（编译型单仓/解释型/异构多语言）。

### 长跑任务启动前置检查（2026-10-06 实证回写）
启动任何小时级训练/评测长跑**之前**，编排者必须：① `pgrep -f <脚本名>` 查有无可比在跑实例；② 查目标 run 家族最新目录的 metrics mtime 判活；③ 若已有同 config 在跑（尤其用户手动触发的"择机档"），**上报并等待裁决，不得另起一路**——双跑互踩实测吞吐 1600→1153 tok/s，且产生两条平行曲线账目混乱。

## 〇、编排文档（阶段 4 产物 · 派发唯一依据）

**存在理由（反事实检验）**：若没有它，次序/授权/凭据/释放四类承诺只活在会话记忆里——R18 实证"资源释放后闲置旁观，等用户提醒才想起自己写过的欠账"、R19 实证"'完成'声明先于落盘验证"，两者的共同上游就是**纪律无当场载体**。故规划落定必须产出 `openspec/changes/<一级变更>/ORCHESTRATION.md`，此后**派发以它为准、核销以它对照**。

**写法＝金字塔原则**：结论先行 → 归类分组（MECE）→ 逻辑排序。四层顺序**不得倒装**，每层只回答上一层的一个问题。

```
# <变更名> 编排文档

## 一、结论（先行）
- 抵达 DoD 的唯一路径：一句话
- 当前最大风险/瓶颈 + 现在卡在哪：一句话
（读者据此判断是否需要下钻；此节写不出来说明计划尚未想清）

## 二、编排四问（MECE 分组）
### 2.1 次序 —— 谁先谁后，依据是什么
就绪队列（**派发原子 = 孙任务**，域仅作边界/账目单位，见 §十一）：
| 孙任务 | 所属域 | 前置 | 状态 ready/blocked/in-flight/done | 触碰集（改写文件 ∪ 构建闭包 ∪ 验证读取包） | 派发单号 |
- 并发准入：与在跑单**触碰集相交**者不得并行（串行或合给同一单）
- 关键路径链（与一级 mermaid 红标一致）
- 本轮物理上做不了什么：延到何处 + 触发条件

### 2.2 授权 —— 谁准写什么，越界怎么办
- 写入划片：每个派发单的白名单精确到文件/目录（只含本单孙任务所需），过程件隔离区（R26）
- 共享面归属：编排者单写 or R22 契约冻结后分派；冻结的签名级常数逐条列出（各代理以此为准，不等彼此产物）
- 偏离分级：预授权自决 / 必须上报待裁（agent 不猜"自决是否合法"）

### 2.3 凭据 —— 什么才算完成
- 四查落点（§四）：**按派发单核**，本单哪些勾选项必复跑、哪些必抽查
- 每条孙任务的复跑命令（exit 0 才勾）；训练类 = run-id + 指标存在
- 必亲验数字清单：吞吐/run-id/通过数等，编排者亲自 grep 或复跑（R7）

### 2.4 释放 —— 锁与等待表
| 资源 | 占用者 | 释放条件 | 等待表（释放后谁消费什么） |
- 释放 = 触发：对照就绪队列**当场补派孙任务单**；无 ready 项则显式记空档原因（禁"下一波再说"，R18/R28）
- 付费/共享资源：熔断线 + 分段记账 + 先报价后正式（R17/R20）

## 三、明细层（支撑二节）
派发单-孙任务矩阵（含触碰集与状态）/ 派发要素落点 / 合单判据与预算上限 / 档位与真实路径欠账（R10–R14 遗留面）

## 四、波次台账（边打边回填）
| 波次/派发单 | 四查结论 | 集成验证（命令+退出码+新 run-id） | 跨域裁决 | 账目勾选凭据 | 下轮情报 | 锁释放与队列消费 |
- 无凭据摘要不得写"完成"；计划回写项（§六）同步登记
```

**用法**：① **每次派发前**重读二节（次序＝就绪队列与触碰集准入，授权＝本单白名单），四问任一有变则**先改文档再派发**；② 单完/波后回填四节台账；③ §六 计划回写时同步更新本档，保持"文档—计划—实况"三者一致；④ 收尾归档时本档即编排证据。

## 一、环境预备（派发前 15 分钟，缺一勿发）

1. 工具链达标：解释器/编译器/包管理器满足项目 requires（系统缺时寻 brew/conda/官方安装器）；实证：系统 python 不满足时寻新版。
2. 隔离环境 + 轻装先行：先装轻量测试/静态检查依赖即派纯逻辑域；重依赖随后（多代理并发装包互踩，见 R17）。
3. **预建包骨架**：按规划目录建空声明文件（`__init__.py`/`mod.rs`/`index.ts`）再装 editable/install 依赖——否则映射不到新增顶层包。
4. 探设备能力与关键库版本，作为"环境情报"随令下传。

**并发资源划拨审计（派发前必做，与 venv 预备同级）**
- 共享可变物**收权到编排者**：公共依赖一次性预装（agent 一律禁 pip install——并发装包互踩与锁竞态实证）；git/索引/lock 类文件只归编排者写。
- 设备/配额划片：长跑独占某设备（GPU/NPU/内存池）时，同场所有并发 agent 显式限到另一资源（如"全部 CPU"）；限流类外部 API 声明配额归属与预算顶。
- 写入划片：agent 只勾**本单所列孙任务**（比"本域"更紧）；一级账目与跨域文件归编排者核销（并发写区冲突实证）；跨域合单仅在两域白名单不相交时允许（§十一）。
- 付费/共享资源执行"熔断线 + 分段记账 + 先报价后正式"三件套：账目无成本行 = 任务未完成；冒烟实测出吞吐后再报正式档价，超线即停上报。
- **并发准入依据 = 依赖传递闭包不相交**（R21；孙任务粒度上用**触碰集**判定，见 §十一）：同仓多代理先实测闭包再定并发集，不凭 import 表直觉。闭包探测命令映射：Go `go list -deps ./<pkg>`；Rust `cargo tree -p <pkg>`；TS/JS `npm ls <pkg>` 或 dependency-cruiser；Python `pipdeptree -p <pkg>`（解释型闭包窗口更小，但仍存在：import 解析/类型检查/共享单例都会读到半成品）。

**资源锁必携等待表（waitlist，2026-10-06 用户纠偏所生）**：独占某资源（设备/端口/配额）划拨的**同一时刻**，登记等待面——"该资源释放后谁要消费什么"（延后的补验、被让路的正式档、闲置的小项清单）。**释放事件 = 触发事件**：确认长跑结束/资源归还的动作里必须**当场消费等待表**（派发或直接执行），不得以"下一波再说"入档等人提醒。编排者是驱动器不是信使——波次进行中任何"待您指示"式悬置，若非真裁决点，即为流程债。

## 二、Agent 派发模板（prompt 八要素）

```
① 变更定位：一级 change 名 + 二级子变更目录路径（CLI 不识别嵌套，须显式给路径）
   + **本派发单号与所辖孙任务编号清单**（派发原子=孙任务，见 §十一；不写清单 agent 会自行扩大改动面）
② 环境：所有解释器/测试运行器命令的绝对路径（venv/工具链路径随令下传）
③ 必读四件套：proposal/design/tasks/spec（+项目注释规范章节）；**额外必给一级根 `ORCHESTRATION.md` 的路径**——它不是 openspec artifact，CLI 的 contextFiles 不列它，派发令不显式递路径就永远读不到（次序/授权/释放三节是 agent 自决边界的上位依据）
④ 已就绪资产情报：前序单/前序域的真实产物路径与可 import 的接口签名——免 agent 重探
⑤ 写入白名单：精确到文件/目录；明令"不动他域文件、禁 git commit/checkout"；过程件归置条款必写
   ——一次性探针/补丁/日志只准落约定隔离区（gitignored 或仓库外 /tmp 分域目录），
   禁止散落工作树根（波次乱源 + index 污染源，见 R26）
⑥ 验证纪律：每条孙任务验证命令 exit 0 才勾 [x]；训练类 = run-id+指标存在；
   汇报须附逐条验证输出摘要（passed 数/run-id/关键数字）——供编排者核查的原始凭据
⑦ 质量门自检：本单白名单所及的项目自有质量门（lint/注释棘轮/文档门）必须绿；
   零容忍门须"自清白名单内 finding"（门的具体运行命令随令下发）
⑧ 探针单加"据实回退"分支：失败按 spec 回退场景执行并原样记录报错（这是交付物）；
   附参考源码路径（如主仓/参考实现仓）供 API 考证
⑨ 本单边界与授权分级：显式写明本单物理上做不了什么（延后到哪个波次/轮次、触发条件）、
   允许 agent 以何种替身先行（脚手架/mock/小模型替身，且键与真货分家）、
   何种偏离属预授权、何种必须上报待裁——agent 不应猜"自决是否合法"；
   编译型/解释型同仓并发时必加：窗口内保持本包可编译/可导入（先加新文件后接线，收尾前 build/import 绿），
   验证面禁全仓构建/全仓测试（根/组合根编译会读到他人半成品）
```

任务须自含完成判据（每条孙任务的验证命令即判据）——理想情况下 agent 凭判据自足完成；判据不清的任务先修计划再派。

**纪律**：改文件与跑验证不得与 Write/Edit 同批并行——本系列三次竞态误判皆源于此（测试跑在修正前的旧码上）。

**写后校验三连（agent 纪律，并发环境下必做）**：编辑工具存在"假成功/延迟落盘/占位覆盖/0 字节"故障史。因此——
- 任何关键文件写入后**立即复核**：`wc -l` 符合预期 + `compile`/`import` 过 + 关键锚行 grep 命中；未复核就引用该文件的"测试结果"一律视为可疑。
- 新文件写后必 **tail 三行**核对——尾部可能出现故障性多余 `package xxx` 行（R15 具体形态，多代理各踩过）。
- 大文件改动用**断言锚点小块替换**，禁 sed 行号删改与跨多节一次性拼接；重构前先做带时间戳快照。
- 后台长任务：受管后台或 `nohup … & disown`，防终端挂断信号把进程停成 TN 态（实测静默挂起数小时）。

## 三、推进 SOP（每轮之间编排者六步；轮 = 一次并发派发批，波次仅汇报分组，见 R3）

**派发前**：重读 `ORCHESTRATION.md` 二节四问，确认次序/授权/凭据/释放与实况一致（有变先改文档，再下发）。

```
**派发（就绪队列全并发，按 §〇 授权 + §十一 触碰集准入下发）**→ ① 完成度核查（§四四查，**按派发单核**）→ ② 集成验证：
全量门禁复跑（agent 各自绿 ≠ 整体绿，并发中间态会产生误报，只认最终态）→
③ 跨域情报裁决：agent 带回的他域缺陷报告，先实证真伪（读码/复现），确真则由
编排者修复（唯一能越域者），附回归用例 → ④ 一级账目勾选：每行附凭据摘要，并回填编排文档台账（§〇）→
⑤ 情报下传：本单产物路径与接口签名写进下一轮 prompt 的要素④ → ⑥ 资源释放与队列巡检：
本轮有无锁归还（长跑收官/窗口到期）+ index 形态核对（见 R26）？有则对照等待表与就绪队列
**当场补派孙任务单**（无 ready 项则显式记空档原因），并把队列余量写进轮次总结
```

## 四、完成度核查与重派发协议（每派发单必做，就绪队列清空为止）

理想态是 agent 凭判据自足完成；现实态必须协议化核查。**四查**：

- **查 1：勾选真实性**——逐勾选项复跑其验证命令（成本高则抽查关键项 + 全量测试兜底）；勾了但验证不过 = 假勾，按未完成处理并记录（假勾两次以上的单，重派 prompt 加"逐条粘贴验证输出"要求）。**未勾但有产物**：复跑验证后替其补勾（如实注明），或打回。
- **查 2：产物盘点**——白名单预期文件 vs 实际落地（`git status`/`find`）；计划声明的产物类型逐一存在。spec scenarios ↔ 测试的映射存在性：spec 写了场景而测试找不到对应者 = 遗漏。
- **查 3：数字溯源**——agent 汇报的关键数字（N passed / run-id / 指标 / 编译键）逐个 grep 或复跑核验；对不上的以实测为准并追记。
- **查 4：遗漏检测（计划 vs 实况）**——**本单所列孙任务** vs 勾选状态（域级仅作汇总视图）：未勾项归类（计划内标注"可延后"的放行，其余为遗漏）；对照**目标-任务覆盖矩阵**复查本域，暴露计划没写的任务则触发 §六回写。

### 归因与重派（决策树，含 d 型）

```
验收/集成测试失败 → 先三分归因：
  a. 产品缺陷                    → 修产品（附回归）
  b. 骨架与既定契约语义错位       → 修骨架断言，不改产品（R23）
  c. 环境噪声（并发半成品波及等） → 轮询目标包 build 恢复后复跑
未完成/遗漏 → 归因三型：
  a. agent 未完成（空返/部分/假勾）      → 重派
  b. agent 做错（验证过但逻辑错）         → 域内错重派修复；跨域错走情报裁决（编排者修）
  c. 计划缺任务（覆盖性缺口）             → 先回写计划（§六）再派新任务
重派 prompt 三型：
  · 复跑验证型（空返但有产物）："逐条复跑验证而非重做"——防重复劳动与覆盖
  · 补缺型（部分完成）："以下 N 条未完成/假勾，已有产物在 X，只补缺不重做"
  · 修复型（做错了）：附缺陷证据（traceback/对拍数据/失败测试名），限定修复范围与回归要求
重派后同样过四查，直至该单清零；同一派发单重派 ≥3 次仍不清 → 升级处理：拆小任务或
编排者亲自完成该残余（并在 run notes 记录升级原因）；域内所有孙任务均 done = 该域清零
```

## 五、空返处置（归因 a 的特例，单列以快查）

1. **先验工作区实况再定重做**：查目标文件是否已落地、tasks 是否已勾、测试是否真绿。
2. 重派 prompt 改令"逐条复跑验证而非重做"——空返 agent 往往已完成工作。
3. 仍空返且无产物：拆小任务范围再派。

## 六、计划缺陷回写（执行期的规划复盘，防复发）

执行期暴露的计划缺口（实证五类：目标无任务承载/消费者漏枚举/档位覆盖不全/性能主张无基准/mock 冒充路径验证，及其余新类别）按固定动作回写：

1. **定位类别**：对照反模式 R10–R14 及 §九/§十 新条目归类。
2. **补计划**：在对应子变更 tasks.md 补孙任务并标注来源（如"【P1 教训回写】"）；涉跨域语义的在 proposal/一级文档补边界声明。
3. **补检查**：若该类别 review-checklist 尚无对应检查项，回写 checklist 覆盖性检查节。
4. **记证据**：返工的根因与代价写入当前 run 的 notes（哪一步暴露、若规划期抓住能省多少）。
5. **保编号**：回写反模式时先 `grep` 既有 R 编号与外部引用锚（change 文档会引用 R 编号），新条目接续最大编号，禁止重排既有编号。

## 七、收尾 F 流程（一级直管）

1. F1 全量门禁（CPU + 设备档，修复后总回归）。
2. F2 DoD 核验——用项目自己的 run 工具立收尾 run（吃自己狗粮），逐条附证据；编排者笔误以追加更正行处理（防重写机制下原行不删）。
3. F3 README 导览表（实现↔手册↔runs 三向映射，run-id 逐字符核对）。
4. F4 `openspec archive <name> --yes`；归档后勾 F4。

## 八、验收评审双路法（实现完成后）

- **代码层**：派 CodeReview 子代理（唯一一个），prompt 给足：范围界定方式（git status/diff）、项目契约清单、假绿测试/数值正确性/安全为重点、Critical/Major/Minor 分级输出。评审结论（尤其 Major）逐条修复并附回归，评审-修复-回归闭环。
- **运行层**（编排者亲验，不可代理）：全量 CPU 门 + 设备门复跑；repro 脚本复跑取**新 run-id 链**（证明可重复）；runs 逐 run 核账：config.commit 实取 git HEAD、metrics 单调、notes 结论行齐；数字溯源抽查；性能数字必含预热后热态（冷启动不进决策表）。
- **测试隔离**：对全局可见状态做"不存在/为空"断言是顺序依赖脆断言——单文件绿、全量红；一律改**快照差集**（R16）。
- **修复纪律**：发现即修；修测试不猜常量名（import 生产侧常量）；造"裸数据"优先复制真产物抹键；修复若引入新败，取 traceback 实证再正法，如实记录。

## 九、执行期反模式详版（R6–R20）

- **R6 空返即重做**：agent 空返 ≠ 未完成；重做前先验工作区，重派令改"复跑验证"。
- **R7 信汇报不复验**：agent 报的数字/绿灯必须编排者 grep 校账与全量复跑确认。
- **R8 跨域缺陷无人认领**：agent 白名单不能越域修他域 bug——这类情报恰是并发执行的涌现价值，编排者是唯一裁决与修复点，修必附回归用例。
- **R9 集成只在最后**：每轮之间就做集成验证，并发中间态的失败要在当轮定位。
- **R15 编辑工具假成功**：Write/Edit 返回成功但文件被占位覆盖/0 字节/延迟落盘晚到一步。→ 写后校验三连（§二）+ 新文件 tail 三行核对；index 变体见 R26；凡引用"未复核文件"的结果视为可疑。
- **R16 全局态脆断言**：`X not in sys.modules / os.environ 为空 / 全局缓存为空`类断言被执行顺序污染，单域全绿全量即红。→ 快照差集改写；轮间集成验证（§三②）是其唯一稳定探测器。
- **R17 并发共享资源互踩**：多 agent 同场并发 pip install / 同设备双跑 / 账目共写 / 后台进程被信号停成 TN——各自汇报皆自洽，合体即乱账（吞吐减半、平行曲线、锁竞态）。→ §一并发资源划拨审计先行；账目单点归属；长跑三查后再发射。同仓代码互踩形态详见 R21。
- **R18 锁解无人候（资源释放不消费）**：资源划拨时只登记"谁在用"，没登记"谁在等"；释放事件发生后闲置旁观，等用户提醒才想起自己写过的"空档可清欠账"。→ §一等待表制度 + §三第⑥步释放巡检；被延后的验证项是计划欠账，不是可无限推后的尾巴。
- **R19 编排者假绿（对自身示范 R7 两次）**：补丁脚本 SystemExit/正则空命中后，外层 && 链照走 commit——"完成"声明先于落盘验证；且第一次勘误 commit 又复犯（勘误本身失实）。→ 铁律：任何修复类动作，commit 前必须当场贴 `grep -c`/`bash -n`/exit 码三验输出；无输出 = 未完成，勾选与 commit 都不许先行。
- **R20 计费窗口付离线税**：编译类验证（方言可用性/头缺失/交叉编译判决）不需要目标设备，却在云窗口临场做——传输/环境/工装修复吃掉计费窗口过半（三轮实证）。→ 判定"此工作是否需要设备运行时"：仅编译 → 本地 Docker 交叉工具链零成本迭代；上卡动作一律制品化单文件 bundle，禁临场命令链。

## 十、同仓并发与共享面派发（R21–R26，2026-10-08 某 Go/Python 异构单仓项目三阶段回写后泛化）

- **R21 同仓依赖闭包污染（R17 的同仓形态；适用：编译型单仓最重，解释型/异构亦有）**：多 agent 共改一仓时，编辑污染按**构建系统传递依赖闭包**传导而非目录/包名直觉——编译型：下游测试编译读到上游半成品；解释型：import 解析/类型检查/共享单例同理（窗口更小但存在）。实证：某 Go 单仓存在"上游工具包 → 装配层 → {算法叶子层, 模型工具层, 装配层子包}"三段传递依赖、且装配层直接 import 算法叶子层，任一包半编辑态击穿全部下游测试（两代理各实测一次，等待窗口约 3.5 分钟）。→ ①波次依据 = 闭包不相交（用 §一映射命令实测）；②代理窗口内保持本包可编译/可导入（先加新文件后接线，收尾前局部 build/import 绿）；③下游被波及 = 轮询上游恢复后复跑，红/绿采证用 overlay/备份复原法做实现无关性自证（Go `go test -overlay`；通用等价：拷贝半成品到临时目录替换后再测）。
- **R22 共享面可独立派发（用户指令确立的替代路线）**：默认"组合根/装配面/全局配置由编排者单写"并非唯一解。共享面庞大时：先把**跨模块接线契约冻结为签名级启动常数**（字段名/函数签名/哨兵名/键名写进一级 design，各代理以此为准、不等彼此产物），再按 R21 闭包拆分分派并发代理（通用形态：配置叶子层 ∥ 装配中间层 ∥ 独立模块 ∥ 异构语言工具面 → 组合根接线波 → tests/docs 波；实证：某异构单仓即按此四路并发派发）。契约冻结波不产代码只产常数；异构仓各语言闭包分别计算（Go 面 build 绿 ≠ Python 面 import 绿，各自验收）。
- **R23 骨架错位归因（重派决策树 d 型）**：验收失败三分归因中的 (b) 型——骨架断言与既定契约语义错位时**修骨架不改产品**。三个实证形态：单实例绑单一会话是设计（双会话需两实例而非二次启动）；Stop 是终态（再启动须报错而非静默重启）；模型自决填写的参数不可作确定性断言（"必须命中"改"禁复用旧值"否定式，确定命中交给机制级单测）。错把 (b) 归为 (a) 会修坏正确的产品。
- **R24 门控验收三态与非空转证明**：需真实外部资源的验收用例实现三态门——无门环境变量 → 唯一合法 Skip；有门缺凭据 → Fatal（"缺配置算通过"是假绿）；门开 → 非空转证明：用不可路由端点（如 127.0.0.1:9）跑一次，断言"真发起调用且零产出被拒收"。预算常量集中定义（总调用数/单调用上限/超时）并实际入账。
- **R25 同树对照基准（R13 的双树不可编译形态）**：性能主张挂基准，但新 API 在 before 树不存在导致同一 bench 无法双树编译时，改**同树对照**：新旧 API 同树并存、同 fixture 同进程分别计时，差值即新增开销。判决双记（绝对值+比值+分配数）入 before/after 表；新增开销相对真实调用面 <1% 且换掉的是缺陷面 → 接受并留档。
- **R26 index 污染（R15 变体）**：仓内自证工具（注释棘轮类零容忍门）会执行 `git add -A -N`（intent-to-add）把代理临时件声明进 index——事后卫生门报 tracked-path-missing，且污染后续提交面。→ 代理过程件只落仓库外；波后编排者必跑 `git reset` 清 index 并核对 status 形态（应只剩 `??`/`M`，不出现 `A`）；已进 index 则 `git reset -- <path>` 后再删文件。
- **附带词法坑（迁 prose 入注释槽时，通用规则）**：目标仓零容忍门对**形态**敏感，迁入前先读门的词法规则再落笔——实证（某仓注释棘轮门）：多行 bullet 判 prose（收敛单行）；"legacy/old/前代"等词触发变更残留审计（改描述性措辞）；新文件尾部故障性多余 `package xxx` 行（tail 三行核对，属 R15 形态）。各仓的门规则不同，但"先读懂门再写"的顺序不变。

## 十一、派发粒度：域级 vs 孙任务级（R28，2026-10-12 用户指令"按领域还是粗"确立）

**派发原子 = 就绪孙任务的集合，不是域。** 域（二级子变更）继续承担**边界**职责——四件套上下文、写入白名单的目录归属、spec 场景验收、账目分段；它是"权限与验收的单位"，不再是"调度的单位"。波次仍按 R3 只作汇报分组，调度跟着就绪队列走。

**何时下落到孙任务级**（任一成立即应拆单）：
- 域内只有少数孙任务 ready，其余被前置/资源卡住——整域派发会让 agent 拿到一堆做不了的事；
- 域内混有异构验证面（编译类 ∥ 长跑档 ∥ 文档），耗时长短差一个量级，快项被慢项拖住上报节奏；
- 释放事件到来，但按域登记的等待面里没有"可整域派发"的候选——R18 要求"当场消费"，无最小可派单元时该消费必然落空。

**合单判据**（拆分有固定开销：读四件套 + 环境自检 + 质量门自清，不设护栏就是 agent 数量爆炸）：
- 同域、**触碰同一文件簇**、或共享同一 spec 场景的 ready 孙任务 → **合为一单**（拆开等于重复加载上下文，还制造同文件竞态）；
- 单条孙任务不自含判据者不得单独成单（§二 末：判据不清先修计划）；
- 均摊护栏：单均 <2 条孙任务时，需先在编排文档写下"此次拆分的解锁收益是什么"再拆；收益说不清 → 不拆。

**并发冲突判定 = 触碰集不相交**（R21 在孙任务粒度的形态）：
- 一单的**触碰集** = 本单要改写的文件 ∪ 这些文件的构建闭包（§一 映射命令实测）∪ 其验证命令会读取的目标包；
- 与任一在跑单触碰集相交 → **串行或合给同一单**；同域两条孙任务改同一文件/同一包即属此列；
- 跨域合单仅当两域白名单目录不相交且触碰集不相交，否则越域写违反 R8 的裁决归属。

**账目与核查换单位**：agent 只勾本单所列孙任务（§一）；四查按派发单核（§四）；"重派 ≥3 次升级"的单元是派发单；域清零 = 域内所有孙任务 done 的派生视图，不另立账。
