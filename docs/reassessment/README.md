## 五批核心结论

1. 项目已从“训练配方与决策质量实验”扩展到“Ascend 算子研究”。转向有计划内用户裁决记录，不是跑偏；但顶层目标、旧 spec 与运行队列未同步表达，需要按 05 §R1 对齐。
2. P1 是可用的教学基线：组件与流程真实存在；但正式预测入口默认未启用自研核，校准存在同集拟合历史与冒烟 fallback，裸克隆复现条件未闭合（02）。
3. P2 的证据主要支持组件、替身和局部端到端流程：真 4B 教师从未前向，OPD 默认仍读评测轴且守卫未覆盖该入口，中文/多模态配置未成为训练行为；服务链是真实正面锚点（03）。
4. GDN v3 是有目标形历史读数的研究候选，不是已接入生产训练的交付件：BK 真修待上卡，单文件示例内联前置件与 v2 源码不同步，现有验收脚本存在吞 NaN 与用例缺失，`#1802` 只是局部反向，性能收益预测证据不足（04）。
5. 五项取向已裁定（1-C 双轨 / 2-B 保留判据补性能锚 / 3-A 替身纪律且教师选型开放 / 4-C on-policy 选项蒸馏 / 5-C 支持面分拆+教学点），详见 [05 §5 裁定记录](05-plan-recommendations.md)。

旧版“第一批结论”已并入上表；原文如下留档：

1. 项目已从“训练配方与决策质量实验”扩展到“Ascend 算子研究”。这一转向有计划中的用户裁决记录，不应简单判成跑偏；但顶层目标、旧 spec 与运行队列没有同步表达这次变化。
2. 当前需要重新对齐执行计划。保留有效目标和既有成果，重新确认依赖、支持范围与验证出口，比继续按历史勾选推进更可靠。
3. GDN v3 候选算子的目标形数值结果，不等于 P2 正式训练入口已接入，也不等于其他形状、精度和性能均达标。
4. 原计划中的长工时估算、短卡窗和“底座随时可跑”等表述都需要按具体模型、当前路径和原始证据重核。未取得完整账单，不判定已花费多少或是否超过某一预算。

## 使用边界

- 研究结论允许被后续批次推翻；勘误记录在相应报告，保留原命题及反证。
- 历史运行日志只能证明当时的版本、输入与环境。本次 CPU 实验不能证明 NPU 数值正确。
- “有实现”“组件测试通过”“正式入口调用”“目标档运行”“整体验收”分别记录。
- 评估完成不等于项目完成；建议通过讨论后才成为下一轮实施契约。
- 独立 CodeReview 子代理因配额失败未完成（V10）；主评估者复验清单见 [05 §4](05-plan-recommendations.md)。
