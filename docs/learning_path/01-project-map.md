# 1. 先看懂项目：一次决策经过了什么

## 1.1 从熟悉的函数开始

一个普通软件函数可以把“订单金额”映射成“是否免运费”。模型也可以看作函数 `y=f(x;θ)`：x 是输入，y 是结果，θ 是一大组可训练的数，称作参数或权重。区别在于，普通业务规则通常由人写，模型参数通过数据调整。

System-One 的任务不是输出一篇文章，而是根据一段 state 回答若干结构化问题。例如：state 是“用户要求查询订单”；问题是选择 `查订单 / 退货 / 转人工`。模型给选项打分，程序把分数变成概率和原始选项键。

这里的 `choice` 是多选一，`noul` 表示是／否类判断，`score` 表示离散评分。这些名字属于接口，不是三种不同的神经网络。

## 1.2 一条完整的数据流

```text
原始资料 → 数据转写和切分 → tokenizer → 数字序列
                                      ↓
                             模型 forward（前向）
                                      ↓
                            选项分数 → 温度 → 概率
                                      ↓
                              原始选项键／评分
```

- **数据转写**：把不同数据集转换为统一字段，不等于改变原标签。
- **tokenizer**：把文字切成 token，再映射成整数 ID。token 可以是字、词的一部分或标点，不固定等于一个汉字。
- **forward**：给定权重计算结果。
- **温度**：调整概率的尖锐程度，不是芯片温度。
- **评测**：将预测与独立测试答案比较，并报告数量、误差和耗时。

“选项 A”要对应恰好一个 token，才能用一个分数读取它。即使 P1、P2 都叫 A，它们的 tokenizer ID 也不一定相同。仓库 P1 自训词表与 P2 基座词表使用不同字母编号，这就是接口语义相同而内部编号不同的实例。[证据 P101、G01，见文末]

## 1.3 训练、推理、评测不是一件事

推理固定 θ，输入 x，计算预测。训练先推理，再用损失 L 衡量错误，计算梯度并更新 θ。评测冻结 θ，使用未用于拟合的数据观察表现。

```text
训练：x → 预测 → 与训练答案比较 → loss → backward → 更新参数
推理：x → 预测                                     （不更新参数）
评测：测试 x → 预测 → 与保留答案比较 → 指标          （不更新参数）
```

因此“前向能跑”不能证明“训练能跑”：backward 会调用额外算子，也会保留或重新计算中间量。一个参数被冻结，只表示不更新这个参数；梯度可能仍需穿过它，才能训练更前面的模块。

## 1.4 P1 与 P2 分别想学什么

| 阶段 | 开始时有什么 | 想回答什么 | 主要目录 |
|---|---|---|---|
| P1 | 自己准备数据，随机初始化权重 | 能否从零构建分词、训练、决策和评测闭环？ | `scratch/`，已冻结 |
| P2 | 现成基座，教师、评测和硬件条件 | 在控制变量下，训练配方、扩展能力与算子实现带来什么变化？ | `release/` |

P1 的小模型会完成流程，不代表它具有大模型知识。P2 下载一个大教师，也不代表训练已经用过它。权重文件在磁盘、模型载入内存、实际输出教师分布、学生吃到分布、独立测试有效，是五件需要分别证明的事。

本项目的实际过程比最初计划复杂：在 910B 上写和验证 GDN 反向成为主线。它有教学价值，但候选算子通过某一形状，不等于正式训练链已经接上它。[G03–G06、A08]

## 1.5 kernel 与模型的关系

模型由很多运算组成，例如矩阵乘、归一化和注意力。kernel 是设备执行的一段计算程序。把矩阵乘写成 TileLang kernel，只相当于实现一个更底层函数。

要让它影响最终用户，调用链还要成立：

```text
服务请求 → 模型 → 后端分发 → 自研 kernel → 返回模型 → 用户结果
```

测试直接调用 kernel，相当于单测绕过了服务层。它可以证明被调用的函数正确，却不能证明后端分发真的选了它。

本项目曾出现：独立 parity（对拍）通过，但模型的 mask 分支令部分运算走回 eager（普通框架执行）。这是软件工程中“模块已写好，却没有接入真实路径”的同一种问题，只是这里还多了梯度和设备条件。[P101]

## 1.6 如何读一行实验结果

看到“准确率 75%”，至少问：多少题？什么任务？哪个模型？训练见过这些题吗？随机基线是多少？

看到“六梯度 PASS”，至少问：什么形状和 dtype？比较的是哪个参考？有没有用参考替换中间计算？所有梯度都测了吗？失败配置有没有保留？

看到“快 10 倍”，至少问：同设备同输入吗？有没有等设备完成？是否排除了编译？比较的是单个 kernel，还是端到端请求？

本项目的三个具体例子：

- 正式评测中的 choice 是 40 题，不应把这一小桶的增益写成大型通用基准结论。[P103]
- 一条长文结果是 1/4 命中，虽然可以写成 25%，但样本很少。[P207]
- GDN 目标形某批六项通过，另一个形状的 dk 或 dbeta 仍失败；不能删去失败行后称普遍正确。[A03–A04]

## 1.7 学生练习与解释

1. tokenizer 测试、模型测试、kernel 测试全绿，能否宣布服务可用？
2. 下载了 4B 教师权重，缓存有 512 条伪标，能否说学生从真 4B 学到了知识？
3. 正确性通过但速度更慢，这段实现还有价值吗？

答案：

1. 不能。还要检查正式入口、装配、设备分发及端到端返回；单测没有自动证明接线。
2. 不能。检查产标的模型身份与实际前向记录；本项目有带 `#scaffold-cpu` 后缀的随机替身缓存。[P201–P203]
3. 有，可能是数学参考、教学样例或后续优化基线；但不能称为已实现加速。负结果应与设备、版本和形状一起保留。[P104]
