# 3. P1：从数字序列到决策概率

前置：[张量与梯度](02-tensors-and-gradients.md)。本章解释现有流程，不要求读者训练模型。工程证据见 [P1 评估](../reassessment/02-p1-chain.md)。

## 3.1 BPE 与 embedding 分别做什么

BPE 从小片段出发，反复把常见相邻片段合成较长 token，得到词表。tokenizer 负责文字与整数之间的转换；embedding 则是可训练矩阵 `E:[V,d]`，把整数 i 映射成第 i 行向量。

例如 ID 为 7 只表示词表中的第 7 项，不表示该词“重要程度为 7”。P1 自训词表，而 P2 使用另一套基座词表，不能把 P1 字母 ID 直接移过去。

预训练时，模型看前缀并预测下一个 token；这一阶段输出词表级分布。决策时，只读取选项字母对应的几个分数，是另一种使用模型输出的方式。

## 3.2 attention 是按相关程度取加权和

把每个位置的表示 X 分别投影为 Q、K、V：Q 用于“我在找什么”，K 用于“我有什么索引”，V 是被汇总的内容。这是帮助理解的比喻，不是向量天然自带的业务含义。

单 head 的维度与公式：

```text
Q,K:[T,DK]；V:[T,DV]
Z = Q @ K.T / sqrt(DK)        # [T,T]，位置对位置的分数
P = softmax(Z + mask)         # 每行变成概率
O = P @ V                    # [T,DV]，加权后的内容
```

causal mask 把未来位置屏蔽，避免预测下一 token 时偷看答案。padding mask 屏蔽为凑 batch 长度补进去的位置。二者不是同一个概念，不能因为“没有 padding”就误删因果约束。

RoPE 将 Q/K 的成对分量按位置旋转，使点积包含相对位置结构；LayerNorm 调整一个位置特征的尺度；MLP 对每个位置做非线性加工；残差把分支输出加回输入。它们有助于建模和优化，但“用了残差所以一定不丢信息”不是数学保证。

## 3.3 预训练、SFT、校准各调什么

| 阶段 | 学什么 | 被调整的量 | 常见误解 |
|---|---|---|---|
| 预训练 | 序列的统计规律 | 模型权重 | loss 下降就等于会通用推理 |
| 决策 SFT | 给定 state 和候选，倾向正确选项 | 全量权重或部分参数 | 一定要生成完整答案文本 |
| 温度校准 | 概率有多自信 | 温度参数 | 准确率一定变高，ECE 一定下降 |

对真实标签 k，交叉熵 `L=-log p_k`：给正确答案更低概率，损失更大。soft target 把单个 k 换成概率向量，后章解释。

一次训练 update 通常包含清梯度、forward、loss、backward、optimizer step；checkpoint 保存权重及必要状态。只保存权重可用于推理，不一定足以无损续训，例如优化器动量和随机状态也影响后续训练。

## 3.4 决策读出为什么可以零生成

假设模型最后一个有效位置的 hidden 为 `h:[d]`，选项 A/B/C 对应输出层三行 `W_opt:[3,d]`，则分数 `z=W_opt @ h`，再对这三个分数归一化。它不需要逐 token 生成答案，所以本项目接口约定 `output_tokens=0`。

要核对四个地方：最后**有效**位置而非右侧 padding；字母是单 token；字母顺序和原始选项映射一致；评分后返回原始键而非臆造字段。wide voting（超过字母容量时分组票选）是额外算法分支，有单测并不表示正式数据已经覆盖它。[P101]

## 3.5 温度：改变自信，不改变精确实数下的排序

`p_i = exp(z_i/τ) / Σ_j exp(z_j/τ)`，τ>0。τ 越大，分布通常越平；所有分数除以同一个正数，大小顺序不变。因此单次同选项决策的 argmax 不因温度而改变。有限精度极端值、后续阈值决策及分组聚合需另看，不将该性质无限外推。

### 实验：同一个答案，两种自信程度

只需 Python 标准库，无模型权重。

```python
import math

scores = [2.0, 0.0, -1.0]
def softmax(z, temperature):
    scaled = [x / temperature for x in z]
    m = max(scaled)
    ex = [math.exp(x - m) for x in scaled]
    return [x / sum(ex) for x in ex]

p1, p2 = softmax(scores, 1.0), softmax(scores, 2.0)
assert p1.index(max(p1)) == p2.index(max(p2)) == 0
assert max(p2) < max(p1)
assert abs(sum(p1) - 1) < 1e-12
print('排序不变，自信程度下降')
```

ECE（Expected Calibration Error，常见分桶校准误差估计）比较每个置信度桶的平均置信和实际命中率，再按桶大小加权。它受分桶方式和样本量影响。温度通常按 NLL（负对数似然，也就是对应的平均交叉熵）拟合，**最小化 NLL 不保证测试集 ECE 更低**。

本项目正式评测出现 choice ECE `0.1175→0.2267` 的负结果。[P103] 这不自动说明温度代码错；检查校准集独立性、分布差异、样本量、拟合目标和边界温度。反过来，合成数据上 ECE 改善也不能保证真实数据改善。

## 3.6 三份数据，三个用途

```text
train：拟合模型权重
calibration/validation：选择温度或超参数
held-out test：最后报告泛化表现，不参与上述选择
```

如果 test 缺失，把 calibration 文件复制一份改名 test，内容还是同一批。文件名不同不产生统计独立性。当前 P1 repro 的某条 fallback 正有这一性质；它适合确认流程能串起来，不适合声称独立测试上的校准收益。[P105]

## 3.7 真实困难如何转成工程检查

| 困难 | 前置概念 | 当时容易误判 | 更有效的检查 |
|---|---|---|---|
| 内核测试绿，模型仍走 eager | 动态分发、mask、调用图 | 以环境标签代替调用证据 | 从公开 forward 记录实际核调用和 fallback |
| 校准后 ECE 变差 | NLL、ECE、独立数据 | 调温一定提高所有指标 | 同时保留 before/after 和数据来源 |
| 从源码无法直接复跑 | checkpoint、数据版本、依赖 | 原工作区成功等于裸克隆成功 | 检查 recipe、pin、资产校验和缺件诊断 |
| TileLang 比框架慢 | 调用开销、融合、硬件版本 | 使用专用 DSL 就自然更快 | 相同入口的暖机对照和分项 profiling |

## 3.8 自测与答案

1. 为什么 NLL 下降而测试 ECE 上升并不矛盾？——优化目标不同、数据不同，ECE 还是分桶估计；不能相互替代。
2. “零生成”是否等于“没有模型计算”？——不是，仍计算输入表示和选项分数，只是不进入自回归生成循环。
3. 可以把另一个 tokenizer 的 A token ID 直接拷过来吗？——不能，先验证编码和读出映射。
4. parity 用的是手工拼接的内核前向，是否证明服务已启用这些核？——不能，需要服务→模型→分发的真实消费者证据。
