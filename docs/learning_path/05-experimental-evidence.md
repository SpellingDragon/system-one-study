# 5. 实验证据：结果是真的，解释也可能是错的

前置：[张量与梯度](02-tensors-and-gradients.md)、[P1 训练](03-p1-training-and-decisions.md)。本章把软件测试与统计推断连接起来。

## 5.1 四种检查不要合并

1. **编译／导入**：程序能否被工具链接受？
2. **运行**：指定输入能否执行完，不崩溃？
3. **正确性**：输出是否符合数学、接口和数值契约？
4. **有效性**：真实任务是否获得可信收益，成本是否合适？

四者通常逐层增加条件。一个全零输出可能有限、不崩溃，却完全错误；一个正确 kernel 也可能没有被模型调用。

## 5.2 小样本的百分比很容易误导

1/4 和 100/400 都是 25%，信息量不同。对独立同分布的二元命中，可以用 Wilson 区间表达抽样不确定性。95% 置信区间是方法在重复采样中的覆盖性质，不是“真概率有 95% 概率落在这次区间”这一贝叶斯解释。

### 实验 A：相同比例，不同证据强度

```python
import math

def wilson(hits, n, z=1.96):
    p = hits / n
    d = 1 + z*z/n
    center = (p + z*z/(2*n)) / d
    half = z * math.sqrt(p*(1-p)/n + z*z/(4*n*n)) / d
    return center-half, center+half

small = wilson(1, 4)
large = wilson(100, 400)
assert small[1] - small[0] > large[1] - large[0]
print(f'1/4 区间约 [{small[0]:.3f}, {small[1]:.3f}]')
print(f'100/400 区间约 [{large[0]:.3f}, {large[1]:.3f}]')
```

题目重复、同一来源高度相关时，上述独立性前提可能不成立；多种子、成组 bootstrap、配对比较解决的也是不同不确定性。不要只为得到更窄区间重复同一道题。本项目 32K needle 的 1/4 是方向性读数，不是稳定能力曲线。[P207]

## 5.3 三把误差尺子

对参考 g、实际 a、逐元素误差 `e_i=|a_i-g_i|`：

| 尺子 | 公式 | 注意 |
|---|---|---|
| max_abs | `max_i e_i` | 依赖结果量级；最大值不是所有元素的误差 |
| 全局 rel | `max_i e_i / max_i |g_i|` | 不是逐元素相对误差；参考全零时另定契约 |
| matched_ratio | `mean(e_i <= atol+rtol*|g_i|)` | 依赖误差和参考幅值的逐元素配对 |

它们可以分列报告，但不能把不同形状的 max_abs 与 rel 相除称“改善倍数”。atol/rtol 是契约，不是 dtype 自动给出的唯一正确标准；同时检查输出类型和业务用途。

### 实验 B：最大误差不能推出匹配率上限

```python
import numpy as np

g = np.full(1000, 0.05)
g[0] = 3.7
B = 1.358e-3
a = g.copy()
a[1] += B
b = g + B
atol, rtol = 2**-14, 2**-9
max_a = np.max(np.abs(a-g))
max_b = np.max(np.abs(b-g))
ratio_a = np.mean(np.abs(a-g) <= atol + rtol*np.abs(g))
ratio_b = np.mean(np.abs(b-g) <= atol + rtol*np.abs(g))
assert np.isclose(max_a, max_b)
assert ratio_a >= .99 and ratio_b < .99
print(f'同最大误差：匹配率 {ratio_a:.3f} 与 {ratio_b:.3f}')
```

两种误差分布都具有约 1.358e-3 的最大误差，但前者只有一个位置错到这个程度，后者几乎处处如此。

如果只知道 `e_i <= B`，`|g_i| >= (B-atol)/rtol` 是**保证该位置通过的充分条件**；不满足它不代表失败。因此统计“大幅值位置占 96%”，至多提供一部分保证通过的位置，不能推出“匹配率最高 96%”。

这直接纠正了旧 GDN 教材的“最大误差即底噪、所以 0.99 永远不可达”。真实深链可能难以达标，但需要逐元素误差统计、精度对照和可接受的梯度用途来判断，不能把难做证明成不可能。[A01–A04]

## 5.4 NaN 让错误的失败条件失效

NaN 是“非数值”，如无定义运算的结果。顺序比较 `<、>、<=、>=` 对 NaN 返回 False，`NaN != NaN` 却是 True。不能说“所有比较都是 False”。

```python
import math

x = float('nan')
assert not (x >= 5e-3)
assert not (x < 5e-3)
assert x != x
accepted = math.isfinite(x) and x < 5e-3
assert not accepted
assert math.isfinite(0.0) and 0.0 < 5e-3
assert not (math.isfinite(float('inf')) and float('inf') < 5e-3)
print('有限性与阈值两道条件通过')
```

如果门禁只在 `error >= limit` 时失败，NaN 就绕过去了。正确做法是把有限性和数值契约都判定清楚，同时为 NaN/Inf、全零参考与空张量设计测试。输出有限只是一层检查，绝不是精度通过。[A01]

## 5.5 控制臂提高可归因性，但不是万能证明

探针是用于回答一个问题的小程序，CONTROL 是已知行为的对照。对照失败时，要检查探针、输入、环境、参考和被测实现，而不是直接归罪其中一个。

- 无对照的失败仍有信息，例如进程崩溃或输出含 NaN；只是通常不足以唯一归因。
- 一条对照通过也不能保证目标形的不同分支无错。
- 对照配置不是因为日志写了 `CONTROL` 就自动 known-good。
- 参考替换中间量能隔离下游问题，但同时缩小了测试范围。

本项目同批 rsa 的目标行通过、CONTROL 行失败就是例子。两行都保留：它既不自动推翻目标数值，也不允许宣称整批验收成功。[A03]

## 5.6 单变量和反事实

“把 BK 改成 DK 后正常”说明两种配置走的路径有差别；它没有唯一指出是拷贝、同步还是累加机制坏了。下一步设计能区分候选原因的实验，不把一个故事写得更长就当成根因。

“误差随 T 不单调”也不证明没有累积误差：不同 T 的输入、相消、归一化分母、最大误差位置都可能变化。更可靠的是在相同输入前缀上比较中间状态、绝对与相对误差和逐项来源。[G06、A02]

## 5.7 性能实验的共同分母

设备常异步执行，host 计时不等待完成可能只量到提交；每次都强制同步又可能改变真实性能。先声明测量对象：kernel 时间、一次 forward/backward，还是端到端请求。

同机、同输入、同模型权重与精度；区分编译、warmup、热态；重复测量并报告分布。比较时保留分子分母原始精度，不能把四舍五入到 0.04s 的数当作精确分母。舍入范围不是测量噪声的置信区间。

时间随 chunk 数近似线性，可能来自计算、拷贝、host 循环或 launch。仅凭直线不能分解各项占比；需要 profiler 或一次只改一个机制的 A/B。

## 5.8 自测与解释

1. 两个实现 max_abs 一样，matched_ratio 一定相同吗？——不，实验 B 展示了反例。
2. CONTROL 过了，目标形 FAIL 就一定是 kernel bug 吗？——不，目标专用输入和参考分支仍可能有错。
3. 只把 test 文件改名 calibration 能消除泄漏吗？——不能，看数据内容和拟合使用历史。
4. 多次运行同一固定 seed 能证明模型泛化吗？——不能，它检验复现稳定性；需要新数据和适当多种子设计。
5. 为什么保留被推翻的解释？——可以学习哪一步缺证据，但应明确标为历史假设，不能继续当作结论。
