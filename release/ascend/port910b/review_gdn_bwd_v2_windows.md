## 二、决策过程的八类系统性缺陷（P1–P8）

### P1 用"文档承诺"替代"能力探针"（最贵）
`design.md` 的三条硬约束（H1 GEMM 域、H2 无 per-token 标量、H3 同步沿用 v1）把全部注意力放在**算法如何映射到 GEMM**；而真正决定成败的是**平台语义**：

| 平台语义 | 何时才被证实 | 若开工首日做的探针 |
|---|---|---|
| 1D→2D 列广播会退化成 `g[0]` | 窗十一 [32]（D15，潜伏 7 个窗口） | 5 行 `T.Parallel` 探针 |
| L0C→GM 的 `realTailN` 随切片含标量退化为 1 | [31]（D13） | 10 行双形态 copy 探针 |
| cv-sync 只对 `workspace_idx` 张量建跨核 flag | [45]（DQ 全 0） | 8 行"普通张量 vs workspace_idx"对照 |
| fp32 plain/transA GEMM 输出 nan/inf | [19]（D7） | 现成的 64³ GEMM 探针 |
| 910B 真实预算 L0C 128 KiB、UB 191.75 KiB | 窗十一 §8 复算 | 读 `codegen_ascend.cc:39` 一行 |

**这五个探针合计 < 50 行、< 半小时**，却能省掉后面五个主要缺陷链的绝大部分返工。这是本次复盘的第一结论：**设计文档回答"算法怎么算"，没人回答"平台怎么坏"**。

### P2 验证输入的退化，使缺陷长期不可见
- `solve_a` 的唯一用例是 g≡0 → 任何索引退化都成立（g 全相等）；
- `scan1` 的 H 链只在 g≡0 验过（S1G 是窗十一才补的）；
- L0 的 basic 是单 chunk + h0=0 → Δ′ 未初始化、dKt 未实现、spill/handoff 别名全部被掩盖。
**常数输入是所有索引类/上下文类缺陷的天然掩体**。这不是运气，是用例设计问题。

### P3 从症状直接跳到机制，绕过了唯一事实源——生成码
DQ 只有 1 列非零 → 猜"累积 GEMM 写一半"（D10，探针否决）→ 猜"L0C 超配"（D11，生成码否决）→ 才去读 `copy_l0c_to_gm` 的四个实参（D12/D13 立现）。两次上卡探针、约 30 分钟，本可由"先 dump 生成码实参"一步到位。

### P4 缺对照就归因
plan-9/9b/10b/10c 全被判定"引入挂死"，直到 [42] 跑**未改一字**的基线才发现基线同样挂。此后所有"谁引入的"结论都失去意义——**没有 baseline 对照的归因不成立**。

### P5 修复方向由直觉（"拆缓冲更干净"）而非约束推导
三次 de-alias（ldk 四槽、vcb 三拆、dvnew 专用）全部回归，代价 3 车 + 三轮代码 churn。真正的约束在 [45]/[46] 才被说清：**cv-sync 只认 workspace_idx；且在 91%/109% 的预算悬崖上，任何 alloc 变化都会改变 liveness 与生成时序**。在这个平台上，"让代码更干净"不是可用目标，"让 codegen 不变"才是。

### P6 探针本身会扰动被测对象
CV 混合核对 liveness 极敏感：同一个 kernel 加一条 dump，生成时序就变。今夜两轮把单点 dump 当 ground truth（[48]/[50]），直到发现**dump 被另一个写点覆盖**（[51]）。探针必须自检不变量，且结论需第二条独立路径。

### P7 替换算子后残留旧算子（D16 的直接成因）
plan-10c 把 P 段的列广播换成"GM 读 GAM"，但被替代的 `T.exp` 留在原位。**两端各自自洽**（GAM 已是 exp 结果；原 exp 在旧语义下正确），只有"替换时未同 commit 删除旧表达式"这一条被违反。七类假设（D9–D15）之后，真正的根因是这一行残留代码——**它从未出现在任何假设列表里，因为没人把"我刚替换了什么、旧的还在不在"当作检查项**。
处置：替换算子必须同 commit 删除被替代表达式；替换后立刻 grep 被替换的符号（本例 `T.exp(aux_ub`）。

### P8 证据不入库
车脚本在 `/tmp`、日志在卡上；实例一停，[46]–[52] 的数字无法复核。已用 `scripts/w11_car.sh`（清单 md5 + flock + 自动归档）纠正。

## 五、如果重来：正确顺序（反事实，可执行）

1. **W1（半天，不上卡）**：写"能力矩阵"5 探针 + 读 codegen 常量定预算 → 产出 `platform_constraints.md`（列播/realTailN/cv-sync 归属/GEMM fp32/预算）。设计文档必须引用它，而不是把它列成"风险点"。
2. **W2**：用 fwd 六件打通"GEMM 域 + 全链"，同时建立**三档输入门**：g≠0、多 chunk、h0≠0（外加 fp32 一档）。此后任何验证不允许只有常数输入。
3. **W3 起**：v2 按"能跑 → 数值 → 性能"三段推进；每个修复强制三件套：**生成码取证 + 对照实验（基线/零输入/反面）+ 日志入库**。
4. **修复顺序**：先修"未初始化读"（Δ′/dKt/WS_D），再修"可见性/时序"（workspace_idx、spill 别名），最后才调数值。今晚的顺序恰好相反，导致 nan 与 0 交织、归因反复。
